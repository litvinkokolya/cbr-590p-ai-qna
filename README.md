# CBR 590-P AI Q&A

Чат-бот для ответов на вопросы по Положению Банка России [№ 590-П](https://www.consultant.ru/document/cons_doc_LAW_220089/) «О порядке формирования кредитными организациями резервов на возможные потери по ссудам».

Реализован на **LangGraph** с использованием **RAG** (векторный поиск по тексту 590-П) и механизма **Human-in-the-Loop (HITL)** для уточнения неполных запросов.

---

## Возможности

- Отвечает на вопросы по 590-П на основе векторного поиска по тексту документа
- При неполном запросе задаёт уточняющие вопросы (HITL)
- Поддерживает многошаговые уточнения — продолжает переспрашивать пока не получит достаточно данных
- Сохраняет контекст диалога при HITL: запрос к FAISS формируется из последних нескольких сообщений пользователя, а не только из последнего
- Ссылается на конкретные пункты положения в ответах
- Обрабатывает ошибки OpenAI API (аутентификация, лимиты, таймаут, сбои соединения)

---

## Схема графа

```
[START]
   ↓
[check_completeness]  ←─────────────────────┐
   ↓                                         │
   ├── данных не хватает → [ask_human]       │
   │                          ↓ interrupt()  │
   │                     ждёт ответа         │
   │                     пользователя        │
   │                          └─────────────►┘
   │
   └── данных достаточно → [retrieve]
                               ↓
                         RAG поиск по 590-П
                               ↓
                        [generate_answer]
                               ↓
                             [END]
```

### Логика работы

1. `check_completeness` — LLM анализирует историю диалога и определяет, достаточно ли данных для точного ответа. Если нет — формулирует уточняющий вопрос
2. `ask_human` — останавливает граф через `interrupt()` и ждёт ответа пользователя. После получения ответа управление возвращается в `check_completeness` (петля)
3. `retrieve` — выполняет семантический поиск по FAISS-индексу 590-П. Запрос формируется из последних 3 сообщений пользователя, чтобы сохранить контекст после HITL-уточнений
4. `generate_answer` — LLM генерирует ответ строго на основе найденных секций, со ссылками на пункты положения

│   ├── test_nodes.py     — юнит-тесты каждого узла графа (с моками LLM)

## Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/litvinkokolya/cbr-590p-ai-qna.git
cd cbr-590p-ai-qna
```

### 2. Создать виртуальное окружение и установить зависимости

```bash
python -m venv venv
source venv/Scripts/activate  # Windows
pip install -r requirements.txt
```

### 3. Добавить API ключ

Создать файл `.env` в корне проекта:

```
OPENAI_API_KEY=sk-...
```

### 4. Запустить чат-бот

```bash
python main.py
```

FAISS-индекс уже включён в репозиторий — переиндексация не требуется.
Если удалить папку `data/faiss_590p_index/`, индекс будет перестроен автоматически при следующем запуске.

## Нарезка документа

Документ разбивается **по структуре**, а не по фиксированному размеру чанков. Каждый нумерованный пункт (1.1., 2.3. и т.д.) вместе со всеми дочерними абзацами образует один Document. Главы (`Глава 1.`) также являются границами разделов.

Это позволяет сохранить смысловую целостность: например, пункт 1.7 с определениями категорий качества I–V попадает в retriever целиком, а не разрезается пополам.

## Примеры диалога

**Неполный запрос — агент уточняет:**
```
Вы:    По сделке качество обслуживания долга плохое. Какую минимальную ставку резерва я могу использовать?
Агент: Укажите категорию качества ссуды (I-V) и тип заёмщика.
Вы:    III категория, юридическое лицо, обеспечения нет.
Агент: Согласно п. 3.11 Положения 590-П, для ссуд III категории качества (сомнительные)
       размер расчётного резерва составляет от 21% до 50% от суммы основного долга...
```

**Полный вопрос — агент отвечает сразу:**
```
Вы:    Какой размер резерва для стандартных ссуд I категории качества?
Агент: Согласно таблице 2 п. 3.11, для ссуд I категории качества (стандартные)
       размер расчётного резерва составляет 0%...
```
